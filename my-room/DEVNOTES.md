# わが家の模型 開発メモ

最終更新: 2026-10-19

間取りの画像を下じきにして部屋の角をなぞり、帖やメジャーの値で縮尺を決め、ドア・窓を置いて 3D で見るツール。くらしラボの1本目。企画は `PLAN.md`。

## しくみ
- **座標**: 単位「u」は下じきの画像のピクセル。画像なしは 1u＝1cm の方眼（5cm きざみに吸いつく）。y は下向き。3D は x＝図の右、z＝図の下、y＝上。
- **画像**: 読みこむときに長い辺 2000px までの JPEG に書きなおす（`prepImage`）。撮影の情報（位置など）は残らない。保存した画像はこの書きなおした後のものなので、u は変わらない。
- **縮尺 `scaleInfo()`**: メジャー（長さを入れたもの）があれば `測った長さ ÷ 図の長さ` の平均（`src:'tape'`）。なければ `√(Σ帖×1.62 ÷ Σ図の面積)`（`'jo'`、推定）。どちらもなく画像があれば長い辺を 10m と仮に置く（`'none'`）。画像なしは 0.01（`'grid'`）。
- **1帖＝1.62㎡ は壁心面積で数える**ルールなので、なぞるのは壁の線のまん中（使い方にも書いた）。
- **壁 `buildWalls()`**: 部屋の辺を m にして、同じ直線（向きの差 0.02rad・ずれ 3cm 以内）ごとにまとめ、区間を合わせる（となりの部屋との壁が2重にならない）。開口は `room:edge` の辺の上の `t`（0〜1、中心）で覚え、その直線の区間から幅の分を抜く。窓は腰壁（床〜sill）と上の壁（head〜天井）を残す。返す `pieces` は `{a,b,z0,z1}`。
- **下じきを回す**: `M.imgRot`（度）。画像は描くときに画像のまん中を軸に回すだけで、画素は書きかえない。回すと、なぞった角とメジャーも同じ軸で回す（`rotatePlan`）ので、画像からずれない。ドア・窓は辺の上の `t` なので回してもそのまま。「壁の線で合わせる」は道具 `align`（メジャーと同じ2点の操作、吸いつきなし）で、線が近いほうの水平・垂直になる角度だけ回す。
- **角を足す・消す**: 「動かす」で部屋をえらぶと辺のまん中に「＋」（画面で 44px より短い辺と、ドア・窓に重なる所には出さない）。押すと角が入り、そのままドラッグ。角を押すだけだと `sel={type:'vert'}` で、「この角を消す」（同じ場所の角＝となりの部屋の角もいっしょ。3つより少なくはしない）。どちらも、その部屋のドア・窓は図の上の位置を覚えて、いちばん近い辺に付けなおす（`keepOpens`）。
- **ふつうの値の出どころ**（2026-10-19 に確かめた）: ドアの通れる幅 75cm・玄関 80cm＝高齢者が居住する住宅の設計に係る指針（平成13年国交省告示1301号）の住戸内の出入口の有効幅員（基本 750mm 以上・推奨 800mm 以上。廊下は基本 780・推奨 850 で、段階C で使える）。窓の 165×110cm・掃き出し窓の高さ 200cm＝日本サッシ協会「標準規格寸法」（2021-04）の内のり高さの基準寸法（300〜2400）と関東間の幅 1650 の例（PDF の文字は化けて読めず、数値の表と例 `16513` で確かめた）。天井の最低 2.1m＝建築基準法施行令21条（2.4m は目安）。壁の厚さ・ドアの高さ・窓の床からの高さは目安（画面にもそう書いた）。
- **3D スキャン**（段階E、`scan.js`）: ファイルはこのブラウザの中だけで読む。三角形の頂点を並べた配列にして、単位（いちばん大きい広がりが 3000 をこえれば mm、60 をこえれば cm、ほかは m）と上の向き（glTF は Y。OBJ・PLY は y と z の広がりの小さいほう）を見当で決める（画面で変えられる）。Z が上なら (x, z, −y) にする。床は、ほぼ上を向いた面の高さの低いほうから 10% の所。
  - 断面の画像: 広がり＋まわり 0.3m を 1m あたり ppm 画素（100、2000 画素をこえるなら小さく）。切る高さ（床から 1m、20〜220cm）で三角形を切った線分を黒い線で、それより下の面（床そのものはのぞく）をうすい灰色で。PNG のまま下じき `IMG` に（`prepImage` は通さない）。`M.scan = {ppm, X0, Z0, floor, slice, name}`。
  - 縮尺: `scaleInfo()` のいちばん先で `M.scan` があれば `s = 1/ppm`、`src:'scan'`（測った値）。推定かどうかは `scaleEst()`（帖から・未設定のときだけ推定）にまとめた。ふつうの画像を読むと `M.scan = null`。
  - 3D: `scanObject()` が半透明の青い形を `V.scene` に足す（`clearGroup` で消えないよう模型の group の外）。図の上の m ＝ (x − X0, z − Z0) で、下じきを回した角度だけ画像のまん中を軸に回す（three の rotation.y は −角度）。2026-10-19 に、4×3m の部屋を cm・Z が上の OBJ で作って確かめた: なぞると 12.00㎡、3D の形と模型の壁がそろう、10° 回してもそろう。glb（ノードの平行移動つき）・PLY（文字・バイナリ）も同じ形で読めた。
  - **壁を自動で見つける**（`scan-walls.js`）: ① 高さ 1m の断面の線の向きを 0〜90° の 0.5° きざみで長さの重みで数え、いちばん多いきざみのまわり ±2° の線の本当の角度の平均を壁の向き θ0 に。三角形を −θ0 回して壁を縦横に。② 上を向いた低い面（床から 10cm 以内）を 2.5cm マスに塗り、6 マス太らせて細らせ（すき間をうめる）、まわりから届かない穴もうめる＝床がある所。③ 天井（下を向いた面の高さを、面の広さの重みでならした真ん中）の 15cm 下（床から 2.25m まで）の断面を壁として 2 マス太らせ、床がある所から引いて、つながった所（0.7㎡ 以上）を部屋に。ドアの上は壁がつながっているので、部屋はドアで分かれる。④ 部屋ごとに、マスの外まわりを縦横の辺の並びにして、15cm より短い辺はとなりの平行な辺と長さの重みで1本に（`orthoSimplify`）。⑤ となりの部屋どうしの向かい合う辺の間（30cm 以上重なるもの）の真ん中の値から、太らせたぶんを引いて壁の厚さ。辺を（太らせたぶん＋厚さの半分）だけ外へずらして壁の中心線に。⑥ 5cm ごとの高さの断面を作り、各辺にそって壁の面（中心線から厚さの半分だけ内）で、高さ 1m に壁がなく天井近くにある所（45cm 以上）を開口に。そこから上下に壁がある高さまでのばして、腰の高さ・上の端。腰の高さ 10cm 以下なら、向こうに別の部屋があれば「ドア」、なければ「掃き出し窓」、ほかは「窓」。幅は両わきの切り口に 1 マスずつ食われるので 2 マス足す。⑦ 模型に入れるとき、下じきを −θ0 回して（`rotatePlan`）部屋が図の縦横にそろうようにし、回した座標 → スキャンの座標 → 画像 → 図の u に直す。壁の厚さ・天井の高さも「測った値」で入れる。
  - 2026-10-19 に、2部屋（4×3m と 3×3m、間の壁 12cm にドア 80×200cm、南に腰窓 160cm・腰 90cm・高さ 110cm、北に掃き出し窓 160×200cm、天井 2.4m、机）のスキャンを OBJ で作り、0°・20°・−35° 回して確かめた: 向き 0・−20・35.001°、部屋 2つ（12.7㎡・9.6㎡、縦横の4角形）、ドア 77〜80cm・高さ 198cm、腰窓 157〜160cm・腰 88cm・高さ 110cm、掃き出し窓 157〜160cm、壁の厚さ 10〜11cm（本当は 12cm。マス目のぶん）、天井 240cm。1回 15〜40ms。
  - ハマったところ: 天井と床の高さを、面の「数」で決めていたら、ドアや窓の上の小さな面（高さ 2.0m）に引っぱられて天井が 2.0m になり、部屋が分かれなかった → 面の広さの重みに。部屋の内向きの向きを逆にとっていて、ドアが「掃き出し窓」になっていた（向こうの部屋を反対がわで探していた）。確かめのときに `confirm` が出て取り消し扱いになり、古い結果を見ていた（コンソールで試すときは `window.confirm = () => true`）。
  - スキャンの形そのものは保存しない（大きい）。断面の画像は下じきとして保存される。USDZ・圧縮された glTF（Draco・meshopt）・別ファイルの .bin を持つ .gltf は読めない（そう出す）。
- **日差し**（段階D、`sun.js`）:
  - 太陽の位置: NOAA の Solar Calculation Details の式（Meeus）。ユリウス日 → 平均黄経・平均近点角・離心率・中心差 → 視黄経 → 黄道傾斜 → 赤緯・均時差 → 真太陽時 → 時角 → 天頂角・方位角、大気の屈折の補正。日の出入りは屈折なしの高さが −0.833° をこえる時刻（10分ごとに調べて二分法）。時刻は日本時間（UTC+9）。年は今年。
  - 2026-10-19 に確かめた値（東京都庁）: 夏至 日の出 4:26・日の入り 19:01・南中 11:43 高さ 77.8°／冬至 6:48・16:32・11:40 30.9°／春分 5:46・17:53・54.1°。よく知られた値と合う。
  - 図の上の向き: 北＝図の上（−y）を `M.north` 度だけ時計回りに回した向き `N=(sin a, −cos a)`、東 `E=(cos a, sin a)`。太陽への向き `d = N cos(方位) + E sin(方位)`。図の右上の矢印（`drawCompass`）と同じ。
  - 日が当たるか（`litAt`）: 床の点 P から d へ水平に線をのばし、壁のかけら（`buildWalls` の区間ごと、壁の中心線）との交点を近い順に。交点までの距離 t の高さ z = t·tan(高さ)。中にいる間: z ≥ 天井 → 天井でさえぎられる。窓の範囲（壁にそった位置と、腰の高さ ≤ z ≤ 上の端）で、窓の外向きと d の内積が正なら外へ出る。それ以外の壁はさえぎる。外へ出たあとも、自分の家の壁に天井より低い所で当たればさえぎる。ひさし（出 D）は窓の上の端の高さにあるとして、通れる上の端 = 上の端 − D·tan(高さ)/cosφ（φ は d と窓の外向きの角）。まわりの建物は軸にそった四角（`M.sun.bldgs`、地面からの高さ）で、光が四角に入る所の高さ（床の高さ＝(何階−1)×2.9m を足す）が建物より低ければさえぎる。
  - 2026-10-19 の見本（北の向き 180°、東京）で手計算と合わせた: 冬至の正午 床 7.5㎡（掃き出し窓から 3.3m 奥、洋室は奥の壁で切れる）、夏至 1.2㎡、ひさし 1m で夏 0・冬 5.3㎡、南 6m に高さ 30m の建物で冬 0（10階なら 6.7㎡）。
  - 3D: 日差しのタブを1度開くと `M.sun.used`。`placeSun()`（view3d.js）が光をその日付・時刻の太陽の向きにする（沈んでいれば目印の光）。部屋の中から見るときの天井も影を作る。
- **搬入**（段階C）: 家具は箱 (w, d, h)。寝かせ方3通り（そのまま・幅を縦に・奥行きを縦に。同じ形は1つにまとめる）ごとに、床の上の長方形 a×b を動かす・回す道を探す。高さが天井より高い寝かせ方は試さない。
  - 壁: `buildWalls()` の直線の区間を、厚さ `wallT()` の長方形に（外の端は厚みの半分のばす）。通れる開口はドア・引き戸・玄関で、床からで（sill 0）、箱の高さ ≤ 開口の高さのときだけ壁から抜く。窓・掃き出し窓は通れない。
  - 箱のまん中が来てよい所（`mask`、5cm マス）: 部屋の中と玄関の外（玄関の外向きに、壁の中心線から 奥行き a+0.6m・幅 max(a,1.5)+1m）。外をぐるっと回って窓から入ることはない（窓は壁）。最初は玄関の外の長い辺を外向きにした置き方。
  - 道さがし（`move-worker.js`）: 位置 2cm（状態が 1600万をこえたら粗く）、向きは箱の端が 2cm くらい動くきざみ（π を nt 等分、箱は半回りで同じ）。各状態のすき間＝箱と壁のいちばん近い距離（分離軸で重なり、角と辺の距離で近さ。上限 6cm）を 0.5cm の段に。隣へ動くとき、平行は step/2、回すと 半対角線×Δθ/2 をすき間から引く（すり抜けない）。段の高い順、同じ段は運ぶ先の部屋の重心に近い順に広げ、箱の4つの角が運ぶ先の部屋に入ったら着いた。着かなければ、いちばん近づいた所を「ここでつかえます」。30秒で打ち切り。
  - 判定: すき間（見つけた道の上の状態のすき間の最小）×2 ＝両側あわせたすき間。境目（`M.move.margin`、初め 5cm）以上で「入る」、0 より大きければ「ぎりぎり」、道がなければ「入らない」。2026-10-19 の見本で: 冷蔵庫（68×70×183）→ LDK はドア 75cm を通って「入る 5cm」（本当は 7cm。マス目のぶん小さめ）、3人掛けソファー（200×90×85）は玄関 80cm でつかえて「入らない」、本棚 → LDK「入る」。パソコンで3通り 2〜3 秒。
  - 推定の注意: 道が通ったドアのうち幅が推定のもの、縮尺が推定かを結果の下に出す。
- **WiFi の計算**（`wifi-sim.js`。まなびラボ `wifi-wave` を写した）: Ez の2次元の波の式を 0.75cm のマス目で解く。場の大きさは家（部屋の外接長方形＋まわり 0.6m）に合わせて変える（外まわり40マスは吸いこむ帯）。上限 420万マス（約 236㎡）。波の出どころから、いちばん遠い角に届いて平均が落ちつくまで（`距離/KC×1.25+800` ステップ）進める。30ms ずつ区切り、`setTimeout` でまわして画面を止めない。終わったら 8×8 マス（6cm）ごとに u² を平均して dBm に（`RED_FS`。換算は wifi-wave の `dbmAt` と同じ: `20 − FSPL(d) + 10log10(e·r/C)`）、読むのはこの縮めた地図だけ。
- **材料のマス目 `wGrid()`**: 高さ 1m で切った面。壁はかけら（`wallSegs()`: 壁の直線を、部屋の辺の端・開口の端で区切ったもの）ごとに、材料の層（wifi-wave の `layers`、cm）をマスに塗る。壁の外の端は厚みの半分のばす。材料: 変えたもの（`M.wifi.wallMat['部屋id:辺']`）→ 2つの部屋にはさまれていれば石こうボード → 1つだけなら外壁（マンション＝コンクリート、木造＝木）。開口: ドア・引き戸＝木（閉めた）、玄関＝金属、窓＝ガラス（高さ 1m が窓の範囲のとき。腰窓の下の壁は壁の材料）。模型の「壁の厚さ」は使わない。
- **もの**（`M.wifi.items`: `{kind, p, rot}`）: 冷蔵庫（金属 65×65cm）・浴槽のお湯（水 110×65cm）・人（水のだ円 46×26cm、wifi-wave の `personM` と同じ）・テレビ（金属の板 120×4cm）。大きさは目安。材料のマス目に、壁のあとで塗る。浴槽は本当は高さ 1m より下だが面の上にあるとして計算（画面に書いた）。
- **中継機**（`M.wifi.ext`、2台まで）: ルーターと中継機の地図を1台ずつ計算して `WS.maps[srcKey(点)]` に覚え、場所ごとに強いほうをとる（`combinedMap()`）。動かしたものだけ計算しなおす。中継機とルーターのつながりは、ルーターの地図を中継機の場所で読んだ値（`extLink`）。−67 dBm より弱いと「中継の速さが落ちやすい（目安）」と出す。おすすめ（★）はルーター1台のときの場所のまま（画面にそう書く）。
- **おすすめ（相反性）**: よく使う場所の印ごとに、印から波を出して縮めた地図を作り、マスごとに最小をとる（＝そこにルーターを置いたときの、いちばん弱い印の強さ）。置ける所（部屋の中・壁から 30cm 以上）のうち、まわり 3×3 の最小がいちばん大きい所が★。予測と「ここに置く」後の値は数 dB ちがうことがある（波の重なり）。2026-10-19 の見本で: 予測 −27、置いたあと −31。
- **2次元の限界**: 上下へにげないので、閉じた部屋では自由空間より強めに出る（見本のベッドで、壁ごしでも自由空間より +3dB）。画面の「簡単にしたところ」に書いた。
- **吸いつき `snapPoint`**: ① 角（12px 以内）② 前の点から水平・垂直（12° 以内）③ ほかの角と x・y をそろえる（8px、点線のガイド）④ 方眼なら 5cm。Shift で②〜④をはずす。角を動かすときは、同じ場所にある角（となりの部屋）をいっしょに動かす。
- **ルーペ**: タッチで点を置く・動かす間、指の位置の2倍を上に出す（キャンバス自身から `drawImage`）。指をはなした所に点が置かれる。
- **3D**: 色は sRGB で書いて `lin()` で直す（r128 の `outputEncoding = sRGBEncoding` のため。直さないと白っぽくなった）。「壁を低く」は 1.1m で切り、切り口を濃い色に。影の光は見やすさのための目印（本物の太陽ではない。段階D で太陽の位置に置きかえる）。
- **保存**: `localStorage` の `kurashi.my-room.v1`（模型）と `.img`（画像の dataURL）、設定は `kurashi.my-room.prefs`。「自動で保存」をはずすと消す。書き出しは `{app, v, model, img}` の JSON。読みこむ画像は `data:image/` で始まるものだけ（外の URL は読まない）。

## 確認のしかた（変更のたびに）
1. http://localhost:8800/my-room/ を開き、コンソールに例外がない・`__roomErr` が空。
2. 「見本で試す」→ 3D に5部屋・ドア・窓が出る（`__room.walls().pieces.length` が 20 前後）。
3. 画像なしで描く → 4点をおおよそでクリックし最初の点で閉じる → 長方形になる（角の座標が 5 の倍数）。
4. 画像を読みこみ → 2部屋をなぞる（2部屋目の角がとなりの角に吸いつく）→ 部屋に「12帖」→ 縮尺が「帖から」。メジャーで2点 → 長さ → 縮尺が「メジャーから」、寸法の表のバッジが変わる。

5b. かたむいた画像で「壁の線で合わせる」→ 壁の線にそって2点 → 壁が水平・垂直になる（`M.imgRot` がかたむきの逆）。左右90°・細かくのつまみ。元に戻すで角度と角が戻る。
5c. 部屋をえらんで「＋」を押す・引く → 角が増える。角を押して「この角を消す」→ 減る。ドア・窓は壁に付いたまま。
6. 再読みこみで模型と画像が戻る。書き出し → 読みこみで同じ模型。元に戻す・やり直す。
6e. 3D スキャン（壁を自動で）: スキャンを読んで「壁を自動で見つける」→ 部屋・ドア・窓が入り、下じきが回って部屋が縦横にそろう。「見つけた形」の行に数と天井の高さ・壁の厚さ。3D で「壁を低く」ならスキャンも 1.1m で切れて、模型と重なって見える。
6e'. 3D スキャン: 「3D スキャンを読みこむ」（または図の上にドロップ）で OBJ・glb・PLY → 断面の下じきと「3D スキャンから」の縮尺。切る高さ・上の向き・単位を変えると下じきが作りなおされる。3D で「スキャンを重ねる」。USDZ は「まだ読めません」。

## ハマったところ
- Browser ペインのスクリーンショットの座標は CSS ピクセルではない（この PC では 0.8 倍）。クリックの位置は `toS()` と `getBoundingClientRect()` から出すか、ページの中でポインターイベントを作って確かめる。
- 合成したポインターイベントでは `setPointerCapture` が例外を出す → try で囲んだ。
- `.row{display:flex}` が `hidden` に勝って、画像がないのに「下じきの濃さ」が出た → `[hidden]{display:none!important}`。
