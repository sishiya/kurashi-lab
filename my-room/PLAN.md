## ねらい
- **5分で自分の部屋の模型ができる**。その模型の上で、WiFi の置き場所・家具の搬入・日差し・家具の配置を計算する（模型を使い回す）。
- 答えだけでなく、**どこでひっかかるか・なぜ日が入らないか**を図で見せる（くらしラボの方針）。
- **入力したもの（間取りの画像・寸法・スキャン）は外に送らない**。ブラウザの中だけで計算し、保存はこの端末とファイルのダウンロードだけ。
- 寸法には「推定（ふつうの値・帖から出した値）」と「測った値」があり、画面でいつも見分けられる。結果の確かさは、推定がどれだけ残っているかで変わることも見せる。

## 形（作る前にユーザーに確かめる。RULES 4章）
- **見る人の手**: 自分で置く・なぞる。
  - 間取りの画像を下じきに読みこむ（ファイルを選ぶ・貼りつけ）。
  - 部屋の角をクリック／タップでつなぐ。直線・直角に自動でそろえる（Shift で解除）。スマホは指の下が見えないので、なぞる場所をルーペで拡大する。
  - 部屋をタップして「6帖」と入れる → 縮尺が決まる。1か所でもメジャーの値を入れれば、そちらを優先する。
  - 壁の上にドア・引き戸・窓・掃き出し窓・玄関を置き、幅を入れる（入れないところはふつうの値）。
  - 天井の高さ・何階か・北の向き（間取り図の方位マークに合わせて回す）。
- **時間の見せ方**:
  - 模型づくりには時間がない（上から見た図と3Dを切りかえるだけ）。
  - WiFi は時間を見せない（電波が落ちついた後の強さの地図だけ。ルーターを動かすと描きなおす）。
  - 搬入は、見つかった運び方を**1本のスライダー**で玄関から部屋まで動かす（自分で進める・戻す）。
  - 日差しは**日付と時刻のスライダー**（1日の中を動かす・季節を動かす）。
- **画面**: 図（上から／3D）とひとことは上に固定。なぞる道具・寸法の表・説明は下へスクロール（スマホ 375px で毎回確認）。はじめての人には、図の上の「つぎへ」1つで、画像を読みこむ → なぞる → 縮尺 → ドア → 3D、の順に案内（1段＝やること1つ）。

## 段階A: 模型（この段階だけで「作って見る」が完結する）
1. 間取りの画像を下じきに（ブラウザの中だけ。端末に保存するときも画像は入れるか選べる）。
2. なぞる: 角をつなぐ・直角にそろえる・やり直し・角を動かす。部屋に名前と帖。
3. 縮尺: 帖から（1帖＝1.62㎡ 以上という広告のルールから推定。地域や物件で差があるので「推定」と表示）、またはメジャーの1か所から。
4. 開口: ドア（開き戸の向き・有効幅）・引き戸・窓・玄関。初期値はふつうの値（推定と表示）。
5. 3D の模型（Three.js。壁の厚み・天井の高さ・開口を抜く）。上から／ななめ／部屋の中から、を切りかえ。
6. 保存: この端末（localStorage）と、ファイル（JSON）のダウンロード・読みこみ。ほかの人に送るのもファイルで（サーバーは使わない）。

## 段階B: WiFi はどこに置く？
- まなびラボの「電波の見える部屋」（`../../アプリ開発/wifi-wave/`、2次元の FDTD を WebGL2 で計算。材料は ITU-R P.2040-3）の計算をもとにする。あちらは「しくみを学ぶ」、こちらは「自分の家で置き場所を決める」。
- 段階A の模型の壁・ドア・窓を材料のマス目に変える。壁の材料は選ぶ（石こうボード・木・コンクリート・ガラス。わからなければ「マンションの外壁はコンクリート、間仕切りは石こうボード」を推定として初期値に）。冷蔵庫・浴槽など電波に効くものも置ける。
- 見せ方: 家じゅうの電波の強さの地図（色）。ルーターをドラッグすると地図が変わる。「よく使う場所」（ソファー・机・ベッド）に印を置くと、そこの強さを並べて見せる。
- **おすすめの置き場所**: ルーターを置ける場所（床・棚の上。コンセントの近く）の候補をいくつか自動でためし、「よく使う場所でいちばん弱い所がいちばん強くなる」場所を出す。なぜそこか（どの壁で弱まるか）も図で。
- 2.4GHz と 5GHz を切りかえ。
- 正直に書くこと: 床に平らな2次元の計算（上下の階・天井・家具の細かい形・鉄筋は入っていない）。受信の強さは**目安**。機種やまわりの家の WiFi でも変わる。
- 作る前に確かめること: wifi-wave の場の広さ（9.6m×6m・1マス 0.75cm）で家がおさまるか。広い家はマス目を粗くするか、場を広げるか（スマホの GPU で動く速さを測る）。コードは wifi-wave からこちらへ写す（MIT。どこから写したかを README に）。

## 段階C: 家具は入る？
- 家具は箱（幅・奥行・高さ）から。ソファー・冷蔵庫・洗濯機・ベッド・本棚のよくある大きさを選べる（ふつうの値。商品名は出さない）。
- 玄関から目当ての部屋まで、水平に動かす・回す・立てる（寝かせる）を組み合わせて通る道を探す（「ピアノの引っ越し問題」。位置×向きの組を細かく区切って探す）。ドアの高さ・天井の高さも見る。
- 結果: 「入る」「ぎりぎり（いちばんせまい所であと何 cm）」「入らない」。ひっかかる場所を赤で、その場所の寸法を測りなおすようにすすめる。
- 正直に書くこと: 計算は箱どうし。本物は梱包・手のすき間・巾木・ドアノブ・照明があるので、ぎりぎりのときは何 cm の余裕を見るか（初期値は推定、変えられる）。
- 段階A の後、作る前に「ソファーの背もたれなど箱でない形が要るか」をユーザーに確かめる。

## 段階D: 日差し
- 場所（緯度・経度。地図を出さず、都道府県を選ぶか数字で。住所は送らない）・北の向き・何階か・窓の位置と大きさから、太陽の位置を計算して、床と壁に日のあたる所を描く。
- 日付・時刻のスライダー。「冬至の正午」「夏至」などのボタン。1日に日があたる時間の地図（床の色）。
- まわりの建物のかげは、最初は「なし」と明記。手で「向かいに高さ何 m の建物」を置けるようにする。PLATEAU（都市の3Dモデル）を使うかは段階F以降で考える（ライセンスと、住所を外に出さずに使えるかを先に調べる）。

## 段階E: 3Dスキャンの読みこみ
- LiDAR のスキャンアプリ（Apple の RoomPlan を使うものなど）が書き出したファイル（glTF・OBJ。USDZ は読めるか調べる）を読み、壁・ドア・窓を段階A と同じ模型の形に変える。変えられないときは、形のまま下じきに表示して、上からなぞる。
- アプリの名前は「このアプリで書き出したファイルが使えます」の説明だけ（宣伝・くらべる形にしない）。どの形式が無料で書き出せるかは、使う前にたしかめる。

## 段階F以降（案）
- 家具の配置（置いたあとの通り道の幅・ドアや引き出しが開くか）。
- まわりの建物（PLATEAU）。
- 家具を箱でない形に。
- 英語対応（入口に載せるとき）。

## やらないこと
- 間取り画像の全自動の読み取り（縮尺がない・肝心の寸法が描かれていない・使えるデータが見つかっていない。IDEAS.md の理由）。
- 賃貸サイトから画像を取ってくること（画像はユーザーが自分で保存したものを読むだけ。サイトの名前も出さない）。
- 入力したものを外へ送ること（サーバー・API・解析に入れない）。
- 「必ず入る」と言い切ること。
- 本物のサービスや不動産サイトの見た目に似せること。

## 簡単にするところ（画面にも書く）
- 壁の厚みは一定（変えられる）。床は水平。
- 帖からの縮尺は推定（1帖の広さは地域・物件でちがう）。
- 段階C の家具は箱。段階D のまわりの建物は、置いたものだけ。

## 出どころ（画面に書く前に、実際に確かめる）
- 1帖＝1.62㎡ 以上: 不動産の表示に関する公正競争規約（施行規則）の該当の条を確かめる。
- 太陽の位置: NOAA の太陽の位置の計算（Meeus『Astronomical Algorithms』にもとづく式）を確かめて使う。
- ドア・廊下・天井のふつうの値: もとにする資料（建築の寸法の本・規格）を確かめてから初期値にする。見つからないものは「目安」と書く。
- 電波: wifi-wave の「おもな出どころ」（ITU-R P.2040-3・ITU-R P.525・IEEE 802.11・Taflove と Hagness 2005）を引きつぐ。受信の境目・ルーターの出力は目安。
- Three.js（MIT）は `lib/` に置き、README とライセンスに書く。
